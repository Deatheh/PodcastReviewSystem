# PodcastReviewSystem

## Назначение
PodcastReviewSystem — это приложение для управления аудио подкастами и сбора отзывов пользователей о них. 
Консольная версия приложения (разработанная в ПР3) дополнена веб-интерфейсом на фреймворке Django (ПР5).

Приложение позволяет:
* просматривать список доступных подкастов в браузере;
* просматривать детальную информацию о конкретном podкасте;
* просматривать список отзывов в браузере;
* просматривать детальную информацию о конкретном отзыве;
* проверять корректную обработку ошибок (кастомная страница 404 при отсутствии ресурса или неверном URL).

## Используемые технологии
* **Python 3.x** – основной язык программирования;
* **Django 5.2** – веб-фреймворк для обработки HTTP-запросов и маршрутизации;
* **HTML / CSS** – разметка и стилизация веб-страниц;
* **Bootstrap 5.3** – CSS-фреймворк для быстрой и адаптивной верстки интерфейса (подключен через CDN);
* **pytest** – автоматизированное тестирование;
* **flake8** – статический анализ качества кода (PEP 8).

## Предметная область
Основными объектами предметной области являются:
* **Подкаст (Podcast)** – аудио контент, доступный для прослушивания и оценки.
* **Пользователь (User)** – человек, оставляющий отзывы о подкастах.
* **Отзыв (Review)** – оценка и текстовый комментарий пользователя к конкретному подкасту.

## Основные сущности (ПР3)

### `Podcast` – подкаст
Объект представляет подкаст.
* Основные атрибуты: `podcast_id` (уникальный идентификатор), `title` (название), `author_id` (идентификатор автора).
* Основные методы: `from_data()`, `to_dict()`, `matches_title()`, `__str__()`.

### `User` – пользователь
Объект представляет пользователя системы.
* Основные атрибуты: `user_id`, `username`, `email`.
* Основные методы: `from_data()`, `to_dict()`, `__str__()`.

### `Review` – отзыв
Объект представляет отзыв пользователя о подкасте.
* Основные атрибуты: `review_id`, `podcast_id`, `user_id`, `text`.
* Основные методы: `from_data()`, `to_dict()`, `__str__()`.

## Страницы веб-интерфейса (ПР5)
Веб-интерфейс реализован с использованием view-функций, возвращающих `HttpResponse` с HTML-разметкой и подключенным Bootstrap.

| URL | View-функция | Назначение |
| --- | --- | --- |
| `/` | `homepage.views.index` | Главная страница: описание приложения и навигация. |
| `/podcasts/` | `podcasts.views.podcasts_list` | Список всех подкастов (загрузка из `data/podcasts.json`). |
| `/podcasts/<int:podcast_id>/` | `podcasts.views.podcast_detail` | Детальная страница подкаста. Возвращает **404**, если подкаст не найден. |
| `/reviews/` | `reviews.views.reviews_list` | Список всех отзывов (загрузка из `data/reviews.json`). |
| `/reviews/<int:review_id>/` | `reviews.views.review_detail` | Детальная страница отзыва. Возвращает **404**, если отзыв не найден. |

*Примечание: Глобальная обработка ошибки 404 настроена через `handler404 = "homepage.views.page_not_found"` в корневом `urls.py`.*

## Назначение модулей

### `main.py`

Консольная версия приложения (сохранена с ПР3). Отвечает за запуск консольного приложения, отображение меню, получение данных от пользователя и организацию пользовательских сценариев.

### `podcast_system/`

Пакет настроек Django-проекта:

* `settings.py` — настройки проекта;
* `urls.py` — маршрутизация верхнего уровня + `handler404`;
* `asgi.py`, `wsgi.py` — точки взаимодействия с сервером.

### `homepage/`

Django-приложение, отвечающее за главную страницу:

* `views.py` — функция `page()` (общий HTML-каркас) и view-функция `index()`;
* `urls.py` — маршрут главной страницы.

Функция `page()` размещена здесь, потому что главная страница задаёт общий вид всех остальных страниц — она точка входа в проект. Остальные приложения импортируют её.

### `podcasts/`

Django-приложение, отвечающее за подкасты:

* `views.py` — view-функции `podcasts_list()` и `podcast_detail()`;
* `urls.py` — маршруты приложения;
* `models.py` — Django-модели (заполняется в следующих работах).

### `reviews/`

Django-приложение, отвечающее за отзывы:

* `views.py` — view-функции `reviews_list()` и `review_detail()`;
* `urls.py` — маршруты приложения;
* `models.py` — Django-модели (заполняется в следующих работах).

### `models/`

Классы предметной области и функции работы с ними (пакет ПР3):

* `podcast.py` — класс `Podcast` и функция `find_podcast_by_id()`;
* `review.py` — класс `Review` и функция `find_review_by_id()`;
* `user.py` — класс `User` и функция `find_user_by_id()`.

### `storage.py`

Отвечает за загрузку и сохранение данных. Содержит:

* класс `StorageManager` — используется консольной версией и тестами;
* свободные функции `load_podcasts()`, `load_reviews()`, `load_users()` — используются Django view-функциями, возвращают готовые объекты предметной области.

### `utils.py`

Содержит вспомогательные функции консольного ввода:

* `input_int()` — безопасный ввод целого числа;
* `input_date()` — безопасный ввод даты.

## Веб-интерфейс (ПР6)
Веб-часть приложения полностью переведена на систему шаблонов Django (Django Template Language). Генерация HTML непосредственно в Python-коде (функция `page()`) больше не используется.

Особенности реализации:
- Используется базовый шаблон `templates/base.html` с переопределением блоков `{% block title %}` и `{% block content %}`.
- Повторяющиеся элементы (навигация, карточки подкастов и отзывов) вынесены в отдельные шаблоны через `{% include %}`.
- Данные передаются из view-функций в шаблоны через словарь контекста.
- Для формирования списков используются циклы `{% for %}` и обработка пустых коллекций.
- Для отображения статусов и наличия данных используются условные конструкции `{% if %}`.
- Все ссылки формируются через именованные URL-маршруты с пространствами имён: `{% url 'app:name' %}`.
- Применяются фильтры шаблонов: `|length` для подсчёта элементов, `|default` для резервных значений.
- Подключены собственные статические файлы: CSS (`style.css`), JavaScript (`main.js` для автоматического вывода текущего года) и изображения через `{% load static %}`.

*Примечание: На текущем этапе данные по-прежнему хранятся в JSON-файлах, Django ORM и формы не используются.*

Содержит автоматизированные тесты проекта.
